## 1. 这张卡到底是什么

### 1.1 载体结构

```
v5.6.png
└─ tEXt:chara (= ccv3, 内容相同)
   └─ data.extensions
      ├─ tavern_helper.scripts[0]  addon-mvu        ← 12 行远程加载器
      │     import 'https://…/tavern_helper_template-main@v0.0.33/dist/addon-mvu/index.js'
      │     （介绍自称：世界时局与经济简报变量脚本、悬浮球前端）
      ├─ tavern_helper.scripts[1]  工作流助手v0.0.33  ← 同样是远程 import，
      │     ↑ 卡里带的 117 字节 content 只是 import 语句，
      │       **真正的资产是它的 `data` 字段（537KB 配置）**
      └─ regex_scripts[0..3]                        ← 4 条正则（3 条渲染 + 1 条剥离）
```

**关键认知：这张卡本身不含引擎代码**，引擎（工作流助手）是远程 ESM。卡里值钱的是 `data` 里那份**配置 + 5 组提示词**（共 196KB 纯提示词）。所以"分析其中代码"实际是分析**它的编排设计与提示词工程**——这也正是能移植的部分。

### 1.2 工作流助手 = 通用「正文后多任务编排器」

`data` 顶层字段（29 个）里，真正定义架构的是：

| 字段 | 值 | 作用 |
|---|---|---|
| `tasks[5]` | 见下表 | 5 个后处理任务 |
| `presets[4]` | 空模板 / 副本族示例 / 正文润色示例 / **世界后台引擎** | 整套配置可切换 |
| `contextTurnCount` | 5 | 每个任务只看最近 5 轮 |
| `contextExtractRules` | `<tp>…</tp>`、`<gametxt>…</gametxt>` | **只抽取正文标签内的内容**当上下文，剥掉状态栏噪音 |
| `chatExtractTags` | user: `StoryEngine`/`QuestPlan` | 从用户楼层抽这两个标签 |
| `messageVarRetention` | `{enabled, keepFloors: 20}` | 消息楼层变量只留最近 20 层 |
| `replicaFamilyCleanup` | `{activityRatio: 0.5, cycleRounds: 10}` | 副本族自动淘汰不活跃项 |
| `finalInjectTemplate` | `<资产账本/>` `<自动化系统/>` `<工作流变量更新>{{UpdateVariable}}</…>` | 追加到 **AI 楼层文末** → 由正则渲染成 UI |
| `tagVariableInjectTemplate` | `{{世界状态摘要@world}}` `{{资产账本}}` | 注入「标签变量」位 |
| `userInputEndInjectTemplate` | `{{入场提示}}` `{{后台强关联角色}}` `{{信息接收后台角色}}` | 注入 **用户输入末尾** = 给下一次正文的「导演提示」 |

### 1.3 五任务四阶段流水线（预设「世界后台引擎」）

| stage | 任务 | 调度 | 副本族 | 结构化 | 推荐模型 | 产出标签 |
|---|---|---|---|---|---|---|
| 1 | 世界时局与经济简报 | **世界时间每 1 周**（timeSource 从 `<tp>` 标签解析） | 按世界名 | `addon_json_patch` | deepseek-pro（严格 JSON） | `世界状态摘要@world`、`UpdateVariable` |
| 2 | 角色筛选与交互 | 每回合 | 否 | off | deepseek-flash / gemini-pro | `ReplicaEnum`、`入场提示`/`离场提示`/`后台强关联角色`/`信息接收后台角色`、`后台角色交互预演`、`后台新角色`、`当前时间` |
| 3 | 前台角色 / 后台角色 | 跟随 stage2 名单 | **按 NPC 名**（每人一次并发调用） | off | gemini-3-flash（便宜） | `npc@act` |
| 4 | 资产账本 | 每 3 回合 | 否 | off | gemini-3-flash | `LedgerTime`、`资产账本` |

数据流：

```
正文 ──┬─► stage1 世界演化 ──► addon_data.世界[世界名]  (JSON Patch 增量)
       │                     └─► 世界状态摘要@world (散文摘要)
       ├─► stage2 角色筛选 ──► ReplicaEnum{前台名单, 后台名单}
       │                     ├─► cast{入场/离场/强关联/信息接收}
       │                     ├─► 后台角色交互预演 (E001/E002…)
       │                     └─► addon_data.社交圈  (JSON Patch)
       ├─► stage3 ×N ────────► npc@act=<角色名>  (每人一块档案)
       └─► stage4 账本 ──────► 资产账本 + LedgerTime
                                    ↓
        三处回注：标签变量位 / 用户输入末尾（导演提示） / AI 楼层文末（UI 占位）
```

### 1.4 按需注入（`chatWorldbookWriteRules` 3 条）

产出不是无脑全量塞回去，而是写成世界书条目再按规则命中：

- `LedgerTime` + `资产账本` → **constant** 条目，永远注入。
- `npc@act` → **keyword** 条目 + `splitByAttr: true`：**每个 NPC 各成一条**，名字在正文里出现才注入。
- `世界状态摘要@world` → constant，但模板里做了两层过滤：
  - 只输出 `降临 === true` 的世界；
  - **社交圈按关键词命中最近 5 条 user + 5 条 assistant 消息**才注入（关键词 = 圈子名 + 活跃角色名（拆 `·` 分隔的西方名）+ 社群人脉）。

### 1.5 四条正则

| # | 名字 | find | 作用 |
|---|---|---|---|
| 0 | 资产状态栏美化 | `<资产账本/>` | 替换成 `$('body').load(远程 index.html)` → 富 UI 面板 |
| 1 | 自动化系统美化 | `<自动化系统/>` | 同上，另一套面板 |
| 2 | 工作流变量更新美化 | `<工作流变量更新>…</>` | 内联可折叠卡片（默认收起 / 明暗主题切换 / 等宽字体）——**纯展示，无数据注入** |
| 3 | **[不发送]** | 上述四种标签 | `promptOnly: true` + `replaceString: ""` → **发给 API 前剥掉**，只在界面留着 |

> 第 3 条就是 display=markdownOnly / prompt=promptOnly 的分域用法，前端已有同款（见记忆 `regex-view-scope-markdownonly-promptonly`）。

### 2.2 卡里独有的机制（候选移植项）

按「能不能写成确定性代码」分类：

**A. 纯确定性（前端能全算，零 API 成本）**
1. **占卜池** — 易经卦 + 大阿卡那 + 小阿卡那三层随机，作为事件的「宏观/发展/细节」命运锚
2. **因果权重自适应法则** — `R = 个体天花板 / 群体平均值`，按 R 分档决定「群体能不能推翻超凡个体」
3. **驱动力校验 / 静滞判定** — A 命定羁绊 / B 剧情关联 / C 局势关联，三无 → 不演化
4. **角色交互可行性校验** — 硬否决（时间悖论/物理绝缘/信息真空）+ 空间距离 4 级 + 信息通路 4 级 + 状态动机
5. **认知地理半径** — 按身份定半径，半径外的事对该 NPC「根本不存在」
6. **世界时间驱动调度** — 每过 N 天/周世界时间跑一次（而非每 N 回合）
7. **24h 记账门禁** — 世界时间差 < 24h 且无重大事件 → 整块不输出
8. **四点闭环校验** — `期初 + 流入 − 流出 = 期末`，Pass/Fail 标注
9. **投机价格公式** — `新价 = 旧价 × (1 + 基础趋势[−0.15,0.15] ± 扰动)`，封顶 ±30%；指数 = 按交易热度加权

**B. 结构（数据模型 + 提示词，需要 AI 填但结构前端锁死）**
10. **世界时代演化模型** — 潜在时代（进度 %/萌芽·发展·临界）+ 时代关键转折点（干预方向/强度 → 净干预值 → 定鼎/归墟）+ 岁月史书（正史/特异点）+ 史诗传奇（母题 → 多版本传世轶闻）
11. **传闻流变系统** — 影响力 5 档 + 流变历程节点（真相/传闻描述/**事实偏差**/流变诱因/预计时效）+ 满 5 节点压缩 + 文化烙印 → 升格传奇
12. **事件生命周期** — 世界背景事件(≤5)/当前区域事件(≤3) + 事件脉络按日期追加 + **结算条件** + 三级结算（重大历史 / 活跃派生 / 偶发湮灭）
13. **团体外交八级 + 事件链闸门** — 血盟/盟友/友好/中立/冷淡/紧张/敌对/世仇；跨级必须先走事件链（联姻/贸易协定/停战谈判/宣战/背刺，各有阶段），**禁止先改关系再补事件**
14. **四维声誉** — 官方/民间/暗域/业界 各 6 级，独立升降，**观察者按所属圈子读对应维度**
15. **社交圈（非正式）vs 团体（正式）二分** — 信息只沿社交圈链路传播
16. **NPC 三层记忆** — 近期(8) → 沉淀(8) → 核心(3–5)，衰退压缩 + **关系变化触发旧记忆重解读/篡改**
17. **NPC 行为链 + `[准备登场]` 标记** — 显式声明"下一轮我要上场"
18. **入场/离场提示 + 后台强关联 + 信息接收** — 注入下一次正文的导演提示
19. **世界经济简报** — 大宗商品供需/价格趋势 + 多币种汇率（本期/上期/涨跌）+ 信贷环境 + 投机市场 + 商路 + 经济事件(≤5)
20. **资产账本** — 产业账与个人钱包**严格隔离**、反偷懒配额、产能分流（已售+入库+自用=产出）、常备收支对称、`nextFixedSettle` 固定支出结算日、配装占用 ≤ 库存期末、外派分层
21. **去 `<user>` 中心强制填表** — 「本轮主动机能否在完全不知道 `<user>` 时成立？是/否」，**配额 = 0 人**

### 2.3 明确不建议移植

| 项 | 理由 |
|---|---|
| JSON Patch (RFC6902) 变量协议 | 前端 `<state>` / `<upstore>` / `<tableEdit>` 已成体系且有容错解析（`lenientJsonParse`）。换协议是纯迁移成本，且 patch 的 insert-vs-replace 判错正是这张卡花最多提示词（`WorldPaper_Update_Format` 7 条硬纪律 + op 决策表）去堵的坑 |
| VOID / Weaver / Recorder 人格外壳 | 纯文风包装，与前端「轮回乐园」术语体系冲突，抄进来是污染 |
| 远程加载 HTML UI | 前端是 React，直接写组件；且远程 CDN 依赖违反前端的自包含原则 |
| 副本族通用编排框架 | 前端 `phasePipeline` + `computeFocusList` 已覆盖；泛化成通用框架收益低 |
| 「无审查/无限制」类越狱语句 | 前端预设自有一套，重复注入只是浪费 token |

## 4. 逐项方案

### ① 占卜池 · 叙事指导（P0）

**卡里怎么做**：`task0_group10` 是一段 EJS，前端 rng 抽 5 组 `{易经卦, 3 张大阿卡那, 3 张小阿卡那}`（逆位概率 0.35），注入成 `<占卜池>`；然后强制每个世界事件的 `叙事指导` 字段**原样填写**其中一组：

```
宏观层: "䷿·未济"                        ← 长期命运气候 / 世界底色
发展层: "皇帝(逆位)、节制、力量(逆位)"     ← 当前阶段推进趋势 / 冲突指向
细节层: "星币五、星币四、权杖侍从(逆位)"   ← 噪声 / 局部信号 / 偶发征兆
```

`WorldPaper_Update_Format` 里专门有「叙事指导格式约束」：**必须照抄原文，禁止改写成解释句**。COT 里则强制「占卜解读｜先做」——先输出 `[事件名.叙事指导]原文 → 三层各一句解读 → 本期命运走向一句话`，再推进事件。

**为什么值钱**：这是**用外部随机性打破 LLM 的模式坍缩**。没有它，AI 推演世界事件会反复写同一类走向（阴谋、危机、反转）。塔罗/易经的语义足够宽，能把"这件事接下来往哪走"从模型偏好里拽出来。

**前端落点**：
- 新文件 `src/systems/divination.ts`（纯函数，可单测）
  - `drawDivination(seed: number, count = 5): Divination[]`
  - 用现有 `makeRng`/`seedFrom`（`systems/autonomyCorpus.ts` 已有确定性 rng）播种 → **同一回合重开不跳位**
  - `formatDivinationPool(list): string` → `<占卜池>` 块
  - `DIVINATION_GUIDE_RULE` 常量（三层语义说明 + 照抄铁则）
- 注入点：`runMiscEvolutionPhase`（世界大事）与后续的 ⑥⑦ 事件/传闻阶段
- 数据落点：`WorldEvent` 加 `guide?: { macro: string; dev: string; detail: string }`
- UI：世界大事条目上显示三枚小徽章（卦象符号可直接用 Unicode `䷀`–`䷿`）

**风险**：塔罗/易经词汇可能泄漏进正文。→ 只注入到**演化阶段**，不注入正文；正文侧只读到事件的散文描述。可加一条 `scrub` 类似 `scrubAbyss` 的兜底。

### ② 入场/离场提示 + `[准备登场]`（P0）

**卡里怎么做**：
- stage2 输出 `<cast>` 四个可选字段：

```xml
<cast>
  <离场提示>张三（去码头交货）,李四（回家探母）</离场提示>
  <入场提示>王五（明日返城，会经过主角所在客栈）</入场提示>
  <后台强关联角色>赵六,钱七</后台强关联角色>
  <信息接收后台角色>孙八</信息接收后台角色>
</cast>
```

- 其中三项经 `userInputEndInjectTemplate` 注入 **用户输入末尾**（= 离正文生成最近的位置）：
  ```
  以下是与<角色动态>相关的提示:
  {{入场提示}} {{后台强关联角色}} {{信息接收后台角色}}
  ```
- stage3 的 NPC 档案里，`行为链` 末尾的「后续预测」若判定下轮要上场，**必须标注 `[准备登场]`**，同时把 `关系列表.<角色>.在场` 置 true。

**为什么值钱**：前端的痛点是「NPC 离场 = 事实性消失」——轨道 A 在后台织了行动，但没有任何机制把「他快回来了」告诉正文。`buildPlotGuardInjection` 管剧情线，不管人。这是一条**已经攒好数据、只差最后一公里注入**的链路。

**前端落点**：
- `npcStore.NpcAuto` 加 `readyToEnter?: boolean` + `enterReason?: string`（≤20 字）；离场时记 `exitReason?: string`
- 轨道 A：`npcAutonomy.ts` 的 `decideContractorTick` / `decideNativeTick` 在生成 deed 时，若命中"路过主角所在地/办完事回程/有事要说"类事件 → 置 `readyToEnter`
- 演化侧：`runEntryJudgment` 的输出协议加 `<入场提示>` / `<离场提示>` 两个可选块
- 注入：新增 `promptInjections.buildCastHintInjection()`，排在**注入链最末**（贴近用户输入），内容：

### ④ 因果权重自适应法则（P0）

**卡里怎么做**（`task0_group1`）：

- **第一原则·能力体系锚定**：`R = 个体天花板 / 群体平均值`
  - `R ≥ 1000` → 个体有「降维打击权」，群体物理反抗成功率 = 0%
  - `100 > R ≥ 10` → 可被「精心策划的群体战术 + 重大代价」克制
  - `R < 10` → 群体逻辑（数量/组织度/资源）正常生效
- **第二原则·群体行为因果过滤器**：群体要推翻超凡个体，必须满足至少一项，否则**自动修正为「群体惨败」或「事件流产」**
  - A 外力降维（同等或更高层级个体介入）
  - B 规则内死穴（世界观明确定义的可被凡人利用的弱点）
  - C 自我耗损（该个体已虚弱到 R < 10）
  - D 非直接对抗（政治/信息/经济/信仰重塑瓦解其存在基础）
- **第三原则·自适应映射表**：修仙→境界压制 vs 护山大阵；科幻→技术代差 vs 代码后门；奇幻→血脉神术 vs 屠龙弩炮；克苏鲁→理智值 vs 集体献祭；权谋→信息差 vs 信息茧房
- **执行指令**：每次推演重大历史节点先输出一行 `[因果权重检查]：个体A vs 群体B，R = X，符合/不符合条件 [A/B/C/D]，允许/拒绝该走向`

**为什么值钱**：前端已经有 `bioStrength`（T0–T9）+ `attrCapForTier` + 14 阶位，**R 值可以纯前端机械算出来**，不用 AI 猜。这正是前端一贯的路子（见记忆 `bio-strength-mechanical`：前端机械判定 + 逆运算治幻觉）。

**前端落点**：
- `systems/derivedStats.ts` 或新 `systems/causalWeight.ts`：
  ```ts
  export function powerRatio(indiv: { tier?: string; bioStrength?: string }, crowdTier: string): number
  export function crowdVerdict(R: number): 'dominate' | 'tactics_needed' | 'crowd_valid'
  export function buildCausalWeightInjection(ctx): string   // [因果权重检查] 一行
  ```
  - 阶位差 → R 的换算表用现成的 `attrCapForTier`：`R ≈ cap(个体阶) / cap(群体阶)`
- 注入点：**所有涉及"群体 vs 个体"的生成点** —— 势力演化、领地、万族、世界大事、战斗结算前、任务结算
- 提示词常量 `CAUSAL_WEIGHT_RULE` 进 `promptRules.ts` + `promptRegistry`（组：演化阶段）
- 第三原则的映射表可以做成 `worldRecordStore.Worldview.核心设定` 的派生——按世界类型选行

**契合点**：与已有的 `NUMERIC_RULE`、`bioStrength` 机械判定、`npcGrowthGuard` 是同一套哲学（前端算死、AI 只叙述）。

### ⑥ 世界事件生命周期（P1）

**卡里的结构**：

```yaml
世界背景事件 / 当前区域事件:              # 前者 ≤5，后者 ≤3；不足 2 时可派生
  ${事件名}:
    叙事指导: { 宏观层, 发展层, 细节层 }   # ← 占卜结果原文（见 ①）
    参与角色: string                      # 人物全名或背景集群NPC
    牵涉团体: string
    事件脉络: { ${日期}: "该日进展与走向" } # 只 insert 新日期，禁止整包 replace
    结算条件: string                      # 1~3 条完成/关闭条件
```

结算三分支：
- 足以影响世界历史走向 → 升格为「时代关键转折点」的新节点
- 足以产生后续影响但不改历史 → **派生 1~N 个后续事件**
- 不足以产生后续影响 → 湮灭，移除

**vs 前端现状**：`miscStore.WorldEvent` 是 `{id, time, location, desc}` 扁平 40 条，**只增不结算**、无脉络、无配额、无派生。`buildWorldTimeInjection` 只喂最近 3 条。等于「世界大事」是一本流水账，不是一个活的系统。

**前端落点**：
```ts
// store/miscStore.ts
export interface WorldEvent {
  id: string; time: string; location: string; desc: string;   // 保留（老档兼容）
  // ── 新增（全部可选，老档 = 单节点扁平事件）──
  scope?: 'background' | 'region';        // 配额分别 5 / 3
  guide?: { macro: string; dev: string; detail: string };      // 占卜三层
  actors?: string; groups?: string;
  chain?: { date: string; text: string }[];                    // 事件脉络·只追加
  settleCond?: string;
  settledAt?: number; outcome?: 'historic' | 'derived' | 'faded';
}
```
- 配额裁剪：前端算（`pruneWorldEvents`），不让 AI 自己数
- 结算判定仍由 AI 出，但**派生的新事件走同一条创建闸门**（照物品的 `deferItemCreate` 独占通道，防重复建）
- 提示词 `WORLD_EVENT_LIFECYCLE_RULE` 进 `promptRules.ts`
- UI：`MiscPanel` 加「🌍 世界事件」页签，事件卡显示脉络时间线 + 结算条件 + 三枚占卜徽章
- 注入升级：`buildWorldTimeInjection` 改为「进行中事件的最新 1 个脉络节点 + 结算条件」，比现在的 desc 截断有用得多

### ⑦ 传闻流变系统（P1）

**卡里的结构**：

```yaml
传闻:
  ${传闻名}:
    影响力: 零星耳闻 | 圈内谈资 | 局部焦点 | 全民热议 | 文化烙印
    流传范围: string
    流变历程:
      ${编号}:                       # 只 insert 下一编号，禁止复用
        流变日期: ...
        预计时效: ...                # 到期才结算，未到期本轮不动
        真相: ...                    # 客观事实
        传闻描述: ...                # 流传版本
        事实偏差: ...                # ← 二者的差
        流变诱因: ...                # 推动本次变化的事件
```

生命周期：
- `当前时间 < 预计时效` → 本轮不动（**省 token 的时效闸门**）
- `≥ 预计时效` → 结算：无价值 → 移除；有价值 → 新增流变节点（消退/传播、趋近真相/加深偏差）
- 影响力 = 文化烙印 → **升格进「史诗传奇」**（母题 + 传世轶闻版本），然后移除
- 流变历程 ≥ 5 节点 → 触发压缩：remove 旧节点 + insert 一条总结节点（取最早日期）
- 总数 ≤ 5，< 2 时派生

**为什么值钱**：`真相 / 传闻描述 / 事实偏差` 三分是这套设计里最精妙的一处——它把「世界上流传的说法」和「实际发生的事」显式分开存，于是 NPC 可以基于**错误信息**行动，而这正是"活人感"的核心。前端完全没有这个概念（`narrativeFacts` 只存事实）。

**前端落点**：
- 挂在 `miscStore`（与 worldEvents 同域，走 `applyMiscCommands({domain:'world'})`）
  ```ts
  export interface Rumor {
    id: string; name: string;
    impact: '零星耳闻'|'圈内谈资'|'局部焦点'|'全民热议'|'文化烙印';
    scope: string;
    nodes: { seq: number; date: string; expire: string;
             truth: string; told: string; drift: string; cause: string }[];
  }
  ```
- **时效闸门前端算**：`gameClock.parseGameMinutes` 比较 `expire` vs `worldTime`，未到期的传闻**不进演化输入**（省 token）
- 压缩前端触发：`nodes.length >= 5` → 标 `needsCompress`，演化阶段才带上它
- 注入正文：只注 `影响力 ≥ 局部焦点` 的传闻，且**只给 `传闻描述`（不给真相）** —— 让 AI 写 NPC 时用的是流言版本
  ```
  <市井流言>（NPC 可能引用·不保证属实）
  · [全民热议] 城南米商囤粮抬价 —— 据说已有三户被砸门
  </市井流言>
  ```
  真相只喂给 `<state>` 侧与玩家面板
- UI：`MiscPanel` 「📢 传闻」页签，每条展开显示流变时间线，**真相列默认折叠**（玩家可以选择当上帝或当局中人）

### ⑧ 四维声誉（P1）

**卡里的结构**：官方 / 民间 / 暗域 / 业界，各 6 级：
```
天怒人怨 → 声名狼藉 → 默默无闻 → 小有名气 → 受人尊敬 → 万众敬仰
```
规则要点：
- **可见性前提**：无人知晓的绝对隐秘行为不影响四维，只影响个人恩怨
- 单一行为最多同时影响 3 个维度
- **观察者按所属圈子读对应维度**：江湖/平民看民间；官府/权贵看官方；黑暗团体看暗域；跨圈子取综合
- 复合效应：民间+官方双高 → 「庙堂之高」（招安/封赏）；暗域+业界双高 → 「黑白通吃」；官方高+暗域高 → 「双面身份」（暴露风险随时间累积）；任一跌至天怒人怨 → 该圈子「通缉/追杀」
- 洗白难度独立、不通用；崩塌事件强制重估所有团体对角色的态度

**vs 前端现状**：前端只有 `favorToPlayer`（势力 −100~100）和 NPC 四轴态度（信任/尊重/情欲/沉沦）——**都是"某人/某势力对主角"的私人关系，没有"社会性名声"这一层**。四维声誉正好补上：它是**公共的**，能解释"为什么陌生 NPC 对我是这个态度"。

**前端落点**：
- `playerStore.profile` 加 `repute?: { official: number; folk: number; shadow: number; trade: number }`（存 0–5 档位 index，显示时映射成六级名）
- `npcStore.NpcRecord` 同样加（NPC 也有名声，用于 NPC↔NPC 互动判定）
- **初始态度派生**：`NpcDetail` / 建档时，新 NPC 对主角的初始 `trust/respect` 由「该 NPC 所属圈子 → 读对应维度」推出一个基线，而不是恒定 10
  ```ts
  // systems/reputation.ts
  export function baselineDisposition(npc: NpcRecord, repute: Repute): { trust: number; respect: number }
  ```
- 可见性闸门：AI 想改声誉，必须在指令里带 `witness=` 字段（目击者/物证/传闻），前端无 witness 直接丢弃 —— 照 `NPC_DECENTER_RULE` 的可判定思路
- 复合效应做成**确定性触发器**：`checkReputeCombo(repute)` 返回待触发事件名，喂给任务演化阶段去落成任务/事件
- UI：`PlayerSidebar` 加一个四格声誉条（四色）；NPC 详情页同款

### ⑨ 势力外交八级 + 事件链闸门（P1）

**卡里的层级表**：

| 层级 | 名称 | 行为/维持 | 升级条件 | 降级条件 |
|---|---|---|---|---|
| 8 | 血盟 | 共担覆灭，可代行决策；每期需共同行动否则降 | —（顶级） | 被背刺/核心人物对立/共敌消失 |
| 7 | 盟友 | 共同行动，共享情报；每期至少一次外交合作 | 三次共同行动 + 一次重大共同利益 | 任何板块无合作 |
| 6 | 友好 | 偶尔合作，互通消息 | 一次正式合作 | 一次利益冲突 |
| 5 | 中立 | 默认起点 | 友好示意 | 地盘摩擦/资源争夺 |

| 3 | 紧张 | 摩擦不断，互相提防 | 成功停战谈判 | 一次公开冲突 |
| 2 | 敌对 | 经常冲突，每期自动产生小型冲突 | 一方衰退 + 停战谈判 | 核心人物被杀/重大背叛 |
| 1 | 世仇 | 永不和解，见面必战 | 仅当一方被消灭后终结 | —（最低级） |

**闸门**：跨级升级（及多数降级）**必须先有对应时局事件链推进至终局，再改本字段；禁止先改关系再补事件**。例外直降：核心人物被杀 / 重大背叛 / 公开宣战。

- 宣战（敌对→世仇）：宣战 → 调兵 → 首战 → 持续战 → 决战
- 背刺（盟友→敌对 / 血盟→世仇）：暗中筹谋 → 试探 → 反水 → 公开决裂 → 血仇形成

**角色介入**：调解（紧张/敌对升一级，世仇不可调）；挑拨（友好/盟友/血盟降一级，血盟需重大把柄）；代行（仅血盟，可代开事件链，违逆核心人物意愿 → 血盟降盟友）

**vs 前端现状**：`FactionRecord.relations` 是自由文本 `"F2:敌对;F3:同盟"`，AI 每回合想改就改，无闸门。

- `factionStore.FactionRecord` 加 `diplomacy?: Record<string, { level: 1|2|...|8; since: number; chainId?: string }>`（保留旧 `relations` 字段作展示兼容）

  ```ts
  export const DIPLO_LEVELS = ['世仇','敌对','紧张','冷淡','中立','友好','盟友','血盟'] as const;
  export function canTransition(from, to, ctx: { chainDone?: string; exception?: 'kill'|'betray'|'declare' }): boolean
  export function CHAIN_TEMPLATES: Record<string, string[]>   // 五套模板
  ```

- **闸门在前端**：`applyFactionShortCommands` 里，`diplomacy` 的跨级变更若无对应已完结事件链 且 非例外 → **拒绝 + 日志**（照 `npcGrowthGuard` 的做法）

### ⑩ NPC 三层记忆 + 衰退（P1）

**卡里的结构**（`<npc>` 的 `<dynamic>` 段）：
```
近期记忆: 1.…;2.…      最多 5-8 条，按时间倒序，细节丰富
沉淀记忆: 1.…;2.…      最多 5-8 条，压缩后的版本
核心记忆: 1.…;2.…      最多 3-5 条，永远不会忘
```
维护流程（Step 11 七小步）：
1. 读性格调色盘（底色/主色调/点缀）→ 决定记忆语气、关注点、解读方式
2. 以该角色**有限视角**判断这事重不重要（情感关联/改变认知/主动参与 = 重要）
3. **衰退**：近期满 8 → 最旧的压缩细节移入沉淀；沉淀满 8 → 最不重要的丢弃、重要的浓缩进核心
4. 合并同类：「昨天一起吃饭」+「今天又一起吃饭」→「最近经常一起吃饭」
5. **篡改**：与某人关系变好 → 重新解读过去的负面记忆；变差 → 扭曲过去的正面记忆；创伤 → 封锁/美化/替换
6. 人格一致性自检：是否用了全知视角？是否写成白描流水账？语气是否串了别的角色？

**vs 前端现状**：`characterStore.memory` 是扁平列表 + `runMemoryCompressionPhase` 按阈值压缩。没有分层、没有「关系变化触发重解读」。

**前端落点**：
- `characterStore` 的 memory 项加 `tier?: 'recent' | 'settled' | 'core'`（缺省 = recent，老档无缝）
- **衰退前端算**（零 API）：`systems/memoryDecay.ts`
  ```ts
  export function planDecay(mem: Memory[], caps = { recent: 8, settled: 8, core: 5 }): DecayPlan
  ```
  超限的条目**标记**为待压缩，交给 `runMemoryCompressionPhase` 一次性处理（不是每条都调 API）
- **篡改钩子**：四轴态度（`trust/respect`）单回合变化 ≥ 阈值 → 给该 NPC 的记忆打 `needsReinterpret`，下次演化时带上「关系已变，重新解读这几条旧记忆」
- 注入侧：正文/私聊只注 `core` + 最近 3 条 `recent`（`sett1ed` 只在演化阶段用）→ 比现在全量注入省
- UI：`NpcDetail` 经历页把记忆分三栏显示（现有 `LifeStoryBox` 旁边）

### ⑪ 时代演化模型（P2）

**卡里的结构**（`时代快讯` 子树）：

```
世界时代阶段: { 时代阶段, 核心社会组织形式, 主流世界观与思潮, 主要经济模式,
               技术特征, 主导性能源与动力, 关键材料标志, 社会阶级结构,
               生产力与生产关系矛盾, 世界秩序格局 }         # 10 个维度

世界时局演进动态:
  演进驱动力 / 时代差格局
  潜在时代演化: { ${时代名}: { 开始日期, 进度"45%", 状态:萌芽|发展|临界,
                               推动因子, 抑止因子, 描述, 已完结转折点事件影响{} } }
  时代关键转折点: { ${事件名}: { 临界事件:bool, 进度"60%",
                                干预态势{推动力:高|中|低, 抑止力:高|中|低},
                                关联潜在时代, 描述, 总体影响,
                                事件脉络{ ${节点号}: { 起止, 干预方向:推动|抑止,
                                                      干预强度:高|中|低, 描述, 影响 } } } }

岁月史书:
  正史:   { ${演变纪名}: { 前时代称谓, 后时代称谓, 演变起止, 描述, 历史影响, 关键转折 } }
  特异点: { ${名}: { 降临:bool, 分歧源头, 事件记录{ ${分歧纪段}: {…} } } }

史诗传奇: { ${核心母题}: { 基本类型, 核心母题关键词, 史实真相, 流变历程,
                          传世轶闻{ ${版本名}: { 原典:bool, 关键要素, 版本流传范围,
                                                版本成型时代, 内容梗概 } } } }
```

**核心算法（可确定性实现）**：
- 转折点进度 = 已完成节点/预期总节点，**单向线性、不可回退**
- 进度 ≥ 100% → 汇总干预：`每个高强度节点 ±2 / 中 ±1 / 低 ±0.5` 求和 = 净干预值
  - 净值偏抑止 → 「归墟」（事件被遏制，留下创伤）
  - 净值偏推动 → 「定鼎」（事件按原逻辑发展）
  - 净值平衡 → **派生一个后续转折点**
- 潜在时代进度 ≥ 80% → 锁定，标「临界」，**强行派生一个临界事件**决定定鼎/归墟
- 潜在时代逻辑关联 → 自动合并（取最早开始日期，进度/因子重写，已完结影响原文合并按时序）
- 事件脉络 ≥ 5 节点 → 压缩为 1 条
- 「事象剪定」：结局导致世界丧失多元可能性 → 判定剪定，写入特异点，重新推演一条平行正史

**为什么慢热**：它需要跑很多轮才看得出效果（进度是慢慢涨的）。对「一个世界只待几十回合就通关」的乐园流玩法，收益打折。

**前端落点（若做）**：
- 新 store `worldEraStore`（`drpg-worldera`），或挂 `worldRecordStore` 的每世界记录下
- 确定性部分全部前端：`systems/eraModel.ts`
  ```ts
  export function netIntervention(nodes: ChainNode[]): number      // ±2/±1/±0.5 求和
  export function verdictOf(net: number): 'settle' | 'void' | 'derive'
  export function shouldSpawnCriticalEvent(era: PotentialEra): boolean   // ≥80% 且无关联临界事件
  export function mergeRelatedEras(eras: PotentialEra[]): MergePlan
  ```
- AI 只负责：新潜在时代命名与描述、节点文本、结局叙述。**进度、净干预、定鼎/归墟判定全前端算**
- 与已有 `chronicle`（编年史）的关系：**岁月史书正史 = chronicle 的上游**。转折点结算产出的「演变纪」直接投影成 chronicle 的一卷。这样不重复造轮子
- 「演变纪命名规范」那段（禁「蒸汽时代至电气时代」式拼接，宜「环海争贡之乱」式具体事象专名 + 6 个正例 6 个反例）**单独抽成提示词常量非常值钱**，可直接用在 chronicle 的修史阶段

### ⑫ 世界经济简报（P2）

**卡里的结构**：
```
世界经济气候: 整体周期相位(繁荣|衰退|萧条|复苏) + 主要贸易区状态{状态,主导产业,需求品类}
大宗商品市场: 粮食/矿产/能源 各 {供需:紧缺|过剩|平稳, 行情要点, 价格趋势:↑↓→, 主要影响因素}
货币与金融:
  基准计价单位: ${名}(${符号})
  流通货币.${名}(${符号}): { 汇率{本期,上期,涨跌}, 市场情绪, 驱动因素 }
  汇率波动指数 / 信贷环境{状态:宽松|紧缩, 金融机构风险}
投机市场:
  市场整体情绪(狂热|乐观|谨慎|恐慌|萧条)
  主要交易标的.${名}: { 类型:股票|期权|份额, 当前价格, 上期价格, 涨跌, 交易热度, 量能, 驱动事件 }
  期货合约.${商品}: { 近月价格, 远月价格, 基差:升水|贴水|平水 }
  投机指数: { 报, 周涨跌 }
贸易格局: 主要商路.${名}{状态:畅通|受阻, 原因} + 贸易政策.${势力}
经济事件: { ${名}: { 描述, 影响维度, 当前态势:酝酿|推进中|趋稳|消退|转折 } }   # ≤5
```

**确定性公式（直接可抄）**：
```
新价格 = 旧价格 × (1 + 基础趋势因子 ± 随机扰动因子)
  基础趋势因子 ∈ [-0.15, 0.15]
  扰动因子受驱动事件影响（胜利 +0.20 / 败仗 -0.25）
  最终涨跌封顶 ±30%
新指数 = 旧指数 × (1 + 所有标的涨跌幅的加权平均)
  权重按交易热度：高=2 / 中=1 / 低=0.5
周涨跌% = (新指数 - 旧指数) / 旧指数 × 100
首次生成旧指数取 100
市场情绪：多数上涨→乐观/狂热；多数下跌→谨慎/恐慌；暴涨暴跌并存→分化震荡
```
还有一条硬约束：**「货币汇率若看涨或看跌，具体数值就得实际涨或跌，不能保持不动」**——治 AI 写了趋势却不改数字。

**vs 前端现状**：前端有「当地货币」（`miscStore.localCurrencyName/localCurrency`，随世界时间演化）和物品价格世界书（公允价阶梯），但没有宏观经济。

**为什么值得考虑**：前端已经有一堆经济玩法（系统商店 / 交易行 / 私信交易 / 赌坊 / 玩家产业 / 强化费用），但它们各自定价，**没有一个共同的宏观锚**。加一层「本世界当前的物价气候」能把它们串起来（记忆里 P3 经济缝合做的是死货币接汇，这是它的下一步）。

**前端落点（若做）**：
- 精简版：只保留 **大宗商品三类 + 基准货币汇率 + 经济事件 ≤3**，砍掉投机市场/期货（那套对乐园流意义不大，除非专门做一个"证券所"设施）
- `systems/economy.ts` 放价格公式（纯函数 + 单测），AI 只给「驱动事件 + 趋势方向」，**数值前端算**
- 消费方：`SystemShop.genShopItems` 的报价 × 物价系数；`channelTrade` 的公允价 × 系数；`dispatchEngine` 的货币奖励不动（那是乐园侧，与任务世界经济隔离）
- ⚠ 必须与已有的「品级颜色 × 评分 × 分类 × 数量」公允价阶梯**相乘而不是替换**，否则物价世界书那套权威就崩了

### ⑬ 资产账本（P2）

**卡里的设计**（`task4`，是全卡工程量最大的一块）：

**24h 门禁**：`LedgerGapHours` = 距上次结算的世界小时数
- `< 24h` 且无重大结算事件 → **整块 `<资产账本>` 不输出**，只输出 `<LedgerTime>` + 一行 `[LedgerGap] 本轮未触发结算，沿用上次账目数据`
- `≥ 24h` 或发生重大事件（大额交易/开张营业/度过营业周期/战损/收购落地/迁入迁出/投资理财/获得新资产/人事调度/外派派出或归队/制度变更/灾害）→ 全量结算
- **`<user>` 个人随身资金变动不计入重大事件**

**三本账严格分离**：
1. `<user>` 个人钱包 / 背包 / 装备 / 坐骑 / 技能 —— **完全不进账本**
2. 产业流动资金（多币种，各自四点闭环 + 汇率重估 + 折合基准）
3. 各实体的库存 / 人员 / 产能

**四点闭环**（每个关键科目）：
```
期初 + 流入 - 流出 ± 自然增减 = 期末            （物资/装备）
期初 + 收入 - 支出 + 汇兑损益 = 期末            （资金）
已售 + 入库 + 自用 = 产出                       （产能分流）
配装占用 ≤ 期末；可用库存 = 期末 − 配装占用      （仓库 vs 携行）
在岗 + 外派 + 伤病/暂离 = total                （人员）
```
每个等式必须标 **Pass/Fail**，Fail 则标「待补明细」不得给净值。

**反偷懒条款**（治 LLM 记账偷工减料，条条可判定）：
- 建筑「点名制」：资产分布里每种建筑 × N 必须在产能模块出现对应分支（可停工，不可缺席）
- 最小明细配额：每实体 ≥3 类建筑；每产线在「运行状态/投入/产出/品质损耗/瓶颈」五项中给 ≥3 项
- 数字可追溯：任何汇总必须在同实体明细中找得到来源
- **常备收支对称**：禁止只继承支出而省略收入；**「正文未写成交 ≠ 无收入」**，须按 `产线已售 × 单价` 或 `设施 baseIncome × 周期` 推算基线
- 删减禁令：上期已有的常设条目不得静默消失，消失必须写原因（拆除/战损/转移/封存/被占/停租/裁撤…）
- Δ=0 要有原因
- 百分比落地：必须写成 `基数 × 比率 = 绝对值`，只写百分比视为无效
- `nextFixedSettle`（实体级固定支出结算日）：本期跨越该日 → 必须计入薪饷/维护；未到期 → 可不扣但须注明「未到期：下次=…」，**禁止假装已付**

**vs 前端现状**：前端有 `shopStore`（商店/娼馆/铁匠铺 + ShopDO）和 `territoryStore.passiveOutput`，但收益基本是「AI 说给多少就给多少」。没有闭环、没有固定支出、没有库存。

**评估**：这是**工程量最大、契合度最低**的一项。乐园流的核心循环是闯关，不是经营模拟。**建议只取其中三条通用护栏**，不移植整套：

1. **24h/N 回合门禁**（不结算就整块不输出）→ 直接可用于前端所有「周期性但不必每回合跑」的阶段
2. **四点闭环 Pass/Fail** → 用在 `territoryStore.storageItems` 与 `shopStore` 的收支上，做一个 `systems/ledgerCheck.ts`，前端算完标 Pass/Fail，Fail 的项在面板标红
3. **常备收支对称 + 「未写成交 ≠ 无收入」** → 这条是治「玩家开了店，AI 从来不写它赚钱」的良药，成本极低（一条提示词 + 一个前端基线计算）

若将来真要做经营玩法，再回来抄完整版。

### ⑭ 社交圈系统（P2）

**卡里的结构**：
```yaml
/社交圈/${圈子名}:
  性质: 家族血缘|地缘|业缘|趣缘|信仰|集市|黑市|学术|宫廷|军旅
  互动频率: 日常|每周数次|逢集日|逢节庆|季节性往返
  信息范围: 市井流言|码头排班|行会内幕|官场风向|地下交易
  社群人脉: 人群专名（不写具体姓名）
  活跃角色: 人物全名、顿号串联
  关联团体: 正式组织专名 / 无
  关联圈交集: 其他社交圈名 / 无
  当前动态: 近期共同事务（节庆筹备/行会例会/集市换季/学徒出师/邻里互助）
  描述: ≥50 字
```
总数 ≤10。核心命题：**团体 = 正式组织（有章程/层级/权力结构/外交关系）；社交圈 = 非正式人际网（亲缘/地缘/业缘/趣缘）**。信息传播沿社交圈链路，**禁止超距获取**。

动态演化五条：自然扩圈（需多次互动铺垫，不发生在单次偶遇）/ 事件驱动重组 / 枢纽转移（信息枢纽离开 → 信息流速变慢）/ 圈层侵蚀（正式团体挤压非正式圈，或帮派从社交圈蜕变为正式团体）/ 角色位置变化（迁居/改行/婚丧嫁娶）。

**注入策略**（见 §1.4）：**关键词命中最近 5 user + 5 assistant 消息才注入**——圈子名、活跃角色名（拆 `·`）、社群人脉都算关键词。

**vs 前端现状**：前端有 `relationGraph`（NPC↔NPC 关系图）但那是**点对点的边**，没有「圈子」这个中间层。也没有信息传播模型。

**评估**：概念很好，但前端已经有关系图谱 + 势力 + 冒险团 + 公会 + 频道，再加一层「社交圈」有**概念过载**风险。

**折中方案（推荐）**：不新建 store，改为在 `relationGraph.ts` 上加一个**派生的聚类层**：
```ts
export function detectCircles(graph: RelationGraph): Circle[]   // 连通分量 / 标签传播
```
把「圈子」当作关系图的**社区检测结果**（纯计算、零 API），只借用它的两个用法：
1. **信息传播判定**：两个 NPC 不在同一圈且无 ≤2 跳路径 → 拒绝「他听说了」类演化（可判定的防超距）
2. **注入过滤**：正文提到某人时，把他所在圈的其他活跃成员一并给 AI（比现在按 favor 排序更有语义）

真正值得单独抄的是那条 **注入策略**（关键词命中才注入），它对前端的 `structuredRecall` 同样适用。

### 跨批次的共同注意事项

- **存档**：所有新 store 必须进 `saveManager.STORES` + `clearProgress`；⚠ `drpg-ledger` 这个 key **已被物品闸门审计占用**，资产账本若做要换名（如 `drpg-assets`）
- **提示词**：新常量一律进 `src/promptRules.ts` 并注册到 `promptRegistry`（改即生效，无需重导预设）
- **API 路由**：新演化阶段走 `resolveApiChain(featureKey)`，别裸 fetch
- **调度**：新阶段进 `App.tsx` 的 `phases` 声明表 + `settings.phaseSched` 加一行
- **世界时间调度**：卡里的 `schedule.mode='time'`（每 1 周世界时间）前端目前没有等价物 —— 若 ⑥⑦⑪⑫ 要按世界时间跑，需要给 `phaseSched` 加一个 `everyGameDays?: number`，用 `gameClock.parseGameMinutes` 比对 `miscStore.worldTime`。这是一个**独立的小基建**，建议在第二批开始前先做
- **数值权威**：凡是能前端算的（进度、净干预、价格、闭环、R 值、记忆衰退）**一律前端算死，AI 只写散文** —— 这与派遣、强化、bioStrength、开箱的既有做法一致

---

## 6. 一句话总结

这张卡真正的价值不在「世界引擎」四个字，而在它把**「世界不围着主角转」这件事拆成了一堆可判定的机械约束**：驱动力三选一、去中心配额 = 0、认知地理半径、交互可行性四级校验、因果权重 R 值、传闻的真相/描述/偏差三分、外交跨级必须走完事件链。

前端已经有很好的编排骨架（phasePipeline / promptRegistry / 多接口路由 / 轨道 A）和很好的「前端算死、AI 只叙述」传统。缺的正是这些**具体的判定规则**。所以最划算的移植不是那三棵大数据树（时代 / 经济 / 账本），而是 P0 那五条几乎不花钱的闸门。
